# 留存机制设计 · 排除社交后的单机路线

> 状态：方案（待选取落地）
> 日期：2026-10-19
> 前置：已排除圈子、好友、排名等社交机制（监管风险 + 偏离产品本质）
> 关系：本文替代 `搭子监督与好友系统设计.md` 作为留存主线，后者仅留作决策存档

---

## 0. 一条判据

讨论任何留存机制之前，先过这一道测试：

> **把这个机制里的「背单词」抽掉，它还能带来快感吗？**

- 能 → 它是游戏，不是学习工具。**否决**
- 不能 → 它寄生在学习行为上。**可以考虑**

对照：

| 机制 | 抽掉背单词后 | 判定 |
|---|---|---|
| 每日签到领金币 | 还能成立（点一下就行） | ❌ 否决 |
| 抽卡 / 开宝箱 | 完全成立 | ❌ 否决 |
| 好友排行 | 成立（看别人排名本身有快感） | ❌ 已排除 |
| "这个词你 32 天没看还记着" | 不成立（没有学习就没有这个词） | ✅ 采纳 |
| 记忆保鲜度条变绿 | 不成立 | ✅ 采纳 |
| 教材通关徽章 | 不成立（没背完就没有） | ✅ 采纳 |

这条判据比"是否社交"更本质。社交只是它筛掉的一类。

## 1. 粘性的真实来源

常见误解是"加奖励就能留住人"。对小学生产品，真正的留存来自四件事：

| 来源 | 机制 | 为什么有效 |
|---|---|---|
| **启动阻力低** | 今天做什么很明确、只要 6 分钟 | 决定"会不会打开" |
| **进步可见** | 我确实记住了一些东西 | 决定"打开了会不会继续" |
| **有明确终点** | 这册学完了 | 决定"会不会长期用" |
| **不烦人** | 完成就结束，不纠缠 | 决定"明天还回不回来" |

注意最后一条：**主动劝退比诱导加练更能提高留存。** 因为学生记住的不是"我今天学了 40 个词"，而是"这个 App 让我很累"。前者是当天数据，后者是长期印象。

对家长侧，还有第五件事：**效果可证明**。付费者是家长，家长看不见效果就会停。

## 2. 机制设计

### 一、把"今天的任务"变成确定的事

#### 1.1 今日任务卡（首屏）

首页最上方一张卡：

```
今天的学习
新学 10 个 · 复习 12 个 · 约 6 分钟
[ 开始 ]
```

**服务核心**：降低启动阻力。小学生不会自己规划"今天该复习哪些"，需要被告知一个明确的、小到不害怕的量。

**为什么不是游戏**：它只是把已有的 FSRS 队列翻译成人话。抽掉背单词，这张卡没有内容可填。

实现要点：`due` 计数 + `plan.dailyNewWords`，全是现成数据。时长估算用 `词数 × 18s`（实测均值可校准）。

#### 1.2 完成即劝退

完成当日计划后，结算页不再出现"再来一组""继续挑战"，而是：

```
今天够了 ✓
明天见，明天有 12 个词等你
```

**服务核心**：这条对齐项目已有的"每日负荷硬封顶"原则。稳定节奏是记忆效果的前提，不是每天背得多。

**为什么反直觉但正确**：无底洞式的"还能学"会让用户形成"永远做不完"的印象，第二天就不敢打开了。明确的收尾制造"完成感"，而完成感是回访的最强动力。

**注意**：不要做"连续打卡断了清零"的羞辱式设计。改成保留「最长纪录」，当前计数温和重置，文案里不出现"你已中断"。

#### 1.3 60 秒模式

结算页和首页各给一个"只学 5 个词"的入口。

**服务核心**：碎片时间的启动门槛。等公交的 2 分钟做不了 22 个词，但能做 5 个。做 5 个也比 0 个好——FSRS 的间隔是靠"接触"维持的。

#### 1.4 断点续学

退出后回来，首页直接可"继续上次"，落到上次那道题，不是重头开始。

**服务核心**：中途被打断是小学生高频场景（家长叫吃饭）。重头开始会直接导致放弃。

### 二、让"记忆效果"看得见 —— 最深的一层粘性

这是整套方案里最重要的一组。因为**用户看不见 FSRS 在做什么，所以感受不到产品的价值**。

#### 2.1 记忆强度可视化（保鲜度条）

每个词已有 `stability` 字段（天）。映射成 5 档：

| 档位 | stability | 显示 | 颜色 |
|---|---|---|---|
| 新芽 | < 1 天 | 刚种下 | 浅绿 |
| 幼苗 | 1-3 天 | 在长 | 绿 |
| 小树 | 4-14 天 | 挺稳了 | 深绿 |
| 大树 | 15-29 天 | 很牢 | 青 |
| **常青** | ≥ 30 天 | 记住了 | 金 |

书架页每册显示"常青词 45 / 143"，词表里每行一个小圆点。

**服务核心**：把抽象的记忆状态变成可见的成长。孩子能直观看到"这些词从浅绿变成金色了"。

**为什么不是游戏**：颜色直接映射 `stability`，是真实记忆强度的可视化，不是人为设定的经验值。抽掉背单词，这个条没有意义。

**语言要具体**，不要用"记忆概率 87%"——小学生看不懂概率。用"这个词你 20 天没看还记得"。

#### 2.2 「还记得吗」回访抽查 ⭐ 最推荐

每天开局或结束时，随机抽 3 个**常青词**（≥30 天没看）：

```
这个词你 32 天没看过了
跑 / run
还记得意思吗？
[ 记得 ]  [ 忘了 ]
```

答对 → "你还记着。这就是每天花 6 分钟的意义。"
答错 → 自动降级回复习队列（这本来就是 FSRS 该做的事，顺手处理）

**服务核心**：这可能是整个产品里**唯一一个能让用户直接感知到产品价值的时刻**。用户第一次亲眼确认"我 30 天前学的词还在脑子里"，从此不会再问"背这个有什么用"。

**为什么不是游戏**：它直接暴露真实记忆状态，答错就是答错，不给任何奖励。抽掉背单词，这个词不存在。

成本几乎为零：`stability ≥ 30` 的词从 `progress` 里筛，判分复用 `srs.judge`。

#### 2.3 主指标换成"记住多少"，不是"背了多少"

书架和学习统计里，把展示重点从「已学 143 个」改成：

```
这册记住了 45 个（常青）
在学 62 个
```

**服务核心**："背了多少"是过程指标，"记住多少"是结果指标。导向结果，用户才会认真对待复习而不是一路刷新的。

**这一条同时是"避免变成游戏"的关键**：游戏化产品绝不敢用"真实掌握度"做主指标，因为那个数字涨得慢、不好看。敢用它，说明产品真的在解决记忆问题。

### 三、给长期行为一个终点

#### 3.1 教材通关

**通关定义**：该册**常青词占比 ≥ 90%**（不是"背完一遍"）。

```
三上 · 已通关
143 个词 · 128 个常青 · 用时 47 天 · 复习 9 轮
```

**服务核心**：把"背单词"从无底洞变成有终点的关卡。一册 143 个词的体量正好——够得着，又有成就感。

**注意**：通关条件是"记住"而不是"学完"，这个差别决定了用户会不会真的复习。如果按"学完一遍"算通关，用户会疯狂点"认识"冲进度。

#### 3.2 二十册地图

6 年 20 册做成一条纵向路径，已通关的点亮，在学的显示进度环，没开始的灰着。

**服务核心**：给跨学期的长期行为一个整体感。小学生看不到"6 年后"，但看得到"这条路上我已经走了 3 格"。

**不做**：不做"距离通关还差 X 天"的预测（FSRS 间隔会变，算不准，承诺不准会失信）。

### 四、让练习本身有趣 —— 不靠外部奖励

这是最"正"的方向：**让答题这件事本身好玩，而不是答题换奖励**。

#### 4.1 新增「听音选词」题型

播放发音 → 4 个英文单词选项。

**服务核心**：多通道编码。"形-义"是一条通路，"音-形"是另一条。两条通路都建立，记忆才牢固。这也是真实英语考试的形式（听写、听力）。

**零素材成本**：477 个 mp3 已经打进包了，`manifest.js` 直接能用。

**不与防泄题规则冲突**：现有规则是"题面为英文才出喇叭"，听音选词本身就是听力题，题面是声音，天然成立。

#### 4.2 顽固词档案

错 ≥3 次的词自动进「卡点集」，单独一个入口，可专项连做。

**服务核心**：错误是学习的信号，不是耻辱。把错误集中起来针对性攻破，直接提升记忆效率。

**配套**：每天第一题，从"昨天错得最狠的词"里抽。利用未完成的心理张力，同时直面难点而不是回避。

#### 4.3 连对音阶

连续答对时音效逐级升高（现在是 E5→A5→D6 固定三音）。

**关键约束：只改音高，不给任何分数/倍率加成。**

**为什么这样设计**：给加成会诱导为了连击而乱猜。只给听觉愉悦，是纯粹的即时反馈，不影响任何判定逻辑。抽掉背单词，就没有连对。

#### 4.4 题型轮换

同一批词，四（五）种题型轮换出现，每次进入学习页的题型顺序不同。

**服务核心**：单调是这类产品流失的主因之一。变化本身就提供新鲜感，不需要额外奖励系统。

### 五、让家长看见（替代社交的"被看见"）

这是唯一需要"双用户"思维的模块，也是零成本高回报的一块。

#### 5.1 本机家长报告

入口：设置页里的"家长查看"（4 位数 PIN，防孩子误入）。

内容（全部读本地 Storage，不上传）：
- 本周学习 5 天 / 共 92 分钟
- 常青词从 32 涨到 45
- 顽固词 Top 10（含中文释义，家长能看懂）
- 各教材进度条
- 一段人话总结："这周比上周多记住 13 个词，但周三周四没学。"

**服务核心**：付费者（家长）看见效果，才会允许孩子继续用。这是留存链条上最容易被忽略的一环——**孩子想用但被家长掐掉**，是最常见的流失原因。

**为什么不是社交**：数据不出设备，没有服务端，没有任何人能看到别人。它只是把本地数据换一种展示。

#### 5.2 可截图的周报卡片

每周日生成一张"本周战报"图（Canvas 绘制），可保存到相册。

**为什么不算社交机制**：分享是微信系统能力（`wx.saveImageToPhotosAlbum`），**不是我们提供的社交功能**。我们只产出一张图，用户发给谁、发不发，与我们无关。不做分享得奖励的引导。

## 3. 反模式清单

明确不做的事，附理由：

| 反模式 | 为什么否决 |
|---|---|
| 体力 / 生命值（答错扣血） | 惩罚错误，而错误是学习的必要部分。会让孩子学会"不确定就跳过" |
| 金币 / 商店 / 抽卡 | 引入与学习无关的目标，快速喧宾夺主 |
| 排行榜 / 好友 / 班级 | 已排除，监管 + 心理双重风险 |
| **连续打卡断了清零** | 请假一天就归零，直接导致流失。改为保留"最长纪录" |
| 限时冲刺 / 速度榜 | 小学生会牺牲准确性换速度，与记忆目标直接冲突 |
| 强制分享解锁 | 把学习变成拉人头 |
| 每日签到领奖励 | 签到本身无学习价值，纯外部激励，正是判据要筛掉的东西 |
| 无限模式 / "还能再学" | 破坏每日封顶，制造做不完的压力 |
| 用「记忆概率 %」表达掌握度 | 小学生无法理解概率，且数字会波动，造成困惑 |

## 4. 优先级与工作量

按「效果 ÷ 成本」排序，全部为零后端改造。

| 优先级 | 机制 | 数据是否现成 | 改动范围 |
|---|---|---|---|
| **P0** | 今日任务卡（含时长估算） | ✔ `due` + `plan` | 首页 |
| **P0** | 完成即劝退（结算页文案） | ✔ | 结算页 |
| **P0** | 断点续学 | ✔ 需存 `session` 位置 | session 页 |
| **P0** | 60 秒模式入口 | ✔ | 首页 + 结算页 |
| **P1** | ⭐ 回访抽查 | ✔ `stability ≥ 30` | 新增轻量页面/弹层 |
| **P1** | 记忆强度 5 档 + 书架占比 | ✔ `stability` | 书架 + 词表 |
| **P1** | 听音选词题型 | ✔ mp3 全有 | `srs.js` 加一个 MODE |
| **P1** | 顽固词档案 | ✔ `recordWrong` | 错词本升级 |
| **P2** | 教材通关 + 徽章 | ✔ | 书架 |
| **P2** | 二十册地图 | ✔ `textbooks` | 新增页面 |
| **P2** | 家长报告 + PIN | ✔ 全本地 | 新增页面 |
| **P2** | 周报卡片图 | ✔ | Canvas |
| **P3** | 连对音阶 | ✔ `sfx.js` | 音效微调 |

P0 全是文案和入口调整，一两天能做完，且能立刻验证"劝退"是否反而提升回访。

## 5. 度量：北极星指标的反直觉选择

**不要用「日均使用时长」当北极星指标。**

背单词产品的目标函数与游戏相反：

> **用得越来越少，记得越来越牢。**

理想曲线：每天固定 6-10 分钟，掌握词数稳定上升，复习正确率上升。
使用时长暴涨反而是警讯（说明在反复重刷，或者卡住了）。

应看的指标：

| 指标 | 含义 | 目标 |
|---|---|---|
| 次日回访率 | 今天的用户明天还来吗 | 越高越好 |
| 7 日回访率 | 是否形成习惯 | 越高越好 |
| 单日完成率 | 打开后能不能做完计划 | 越高越好 |
| **常青词增长率** | 真实记忆积累 | 稳定上升 |
| **30 天后正确率** | FSRS 是否工作 | 应接近 0.9 |
| 平均单次时长 | 是否"刚好" | **稳定，不追求增长** |
| 主动退出率 | 完成后是否立即离开 | **高是好事** |

最后一条最能说明产品是否走偏：**如果用户在完成后还赖着不走，说明我们做的是玩具；如果完成后干脆离开、第二天准时回来，说明做的是工具。**

## 6. 一句话总结

留存不靠奖励堆叠，靠三件事：

1. **今天这点事做得完**（确定性）
2. **做完能看见自己变强了**（可见的进步）
3. **不打扰，明天还愿意来**（低摩擦）

这三件都直接长在"背单词"这个行为上，抽掉它就不存在。这就是它不会变成社交游戏的原因。
